The Shield

Raw string concatenation lets attacker input become executable SQL. Parameterized queries treat input strictly as data. Try the classic payload below against this live API.

Vulnerable
query = "SELECT * FROM users
WHERE email = '" + userInput + "'"

String concatenation lets ' OR 1=1 -- close the quote early and rewrite the query's logic.

VaultBase's approach
db.prepare(
  "SELECT * FROM customers WHERE email = ?"
).get(email)

The ? placeholder is bound, never interpolated — the database can never confuse the payload for logic.
